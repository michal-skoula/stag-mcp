## Notes
- `ng_*` namespaces mean "new generation", these are more modern versions of old API namespaces. When available always use these instead of the old ones. HOWEVER, they don't always have 100% feature parity with the old versions, so sometimes it might be needed to call from both the ng and old namespaces.
- some endpoints are noted as being `Negarantováno!` in the docs, meaning they are volatile and subject to change or be removed. These should probably get their own trait getting error messages like "This tool calls a volatile endpoint that isn't guaranteed". If there are multiple endpoints that do the same thing or overlap, prefer ones which aren't unstable.
- `getBudovy` answers anonymous callers; `getMistnostiInfo` in the same namespace returns 401 without a token even though the docs list it as "probably without the need to log in" for both.
- `mistnost/getBudovy` wraps its list in `items`; `mistnost/getMistnostiInfo` wraps its list in `mistnostInfo`. The wrapper key is per-endpoint, not a namespace-wide convention.
- `mistnost/getMistnostiInfo` (2411 rows, unfiltered) always returns null for `provozDo`, `serial`, `urlMistnost`, `identifikatorBudova`; `identifikatorMistnost` and `dvereCislo` are null in all but one row. `typCiselne` duplicates `typ` as a numeric code. Treat these as dead/near-dead columns.
- `mistnost/getBudovy` `provozOd`/`provozDo` data has quality issues, some rows show `provozOd` after `provozDo` (e.g. zkrBudovy A2: provozOd 4.7.2026, provozDo 1.1.2026). Don't assume the range is well-formed.
- `mistnost/getBudovy`'s `gpsBudovaX`/`gpsBudovaY` are longitude/latitude (X=lon, Y=lat). Its `gpsAdresniMistoX`/`gpsAdresniMistoY` are the reverse (X=lat, Y=lon) and redundant with the budova pair. `mistnost/getMistnostiInfo`'s `budovaGPSX`/`budovaGPSY` follow the `gpsBudova*` convention (X=lon, Y=lat). Map explicitly per field name, don't assume X/Y line up the same way across fields.
- `predmety/najdiPredmety` and `predmety/getPredmetInfo` both answer anonymous callers, like `mistnost/getBudovy` (not like `getMistnostiInfo`).
- `predmety/najdiPredmety` wraps its list in `predmetKatedry`. Calling it with zero filters returns HTTP 500, not an empty list or 400 — always send at least one filter.
- `predmety/najdiPredmety`'s `nazev` param is an exact match on the full course title, not a substring search, unlike `GetBudovyTool`'s address filter. A partial title returns zero rows.
- `predmety/najdiPredmety` rows only ever populate `katedra`, `zkratka`, `rok`, `nazev` — every other field (`semestr`, `vyukaZS`, `pocetStudentu`, the `aMax`/`bMax`/`cMax`/`aSkut`/`bSkut`/`cSkut` capacity fields, etc.) is always null. Fetch `getPredmetInfo` for real data.
- `predmety/getPredmetInfo` for an unknown katedra/zkratka combo returns `[]` (empty array), not a 404 or an error — check for that shape rather than assuming an object comes back.
- `predmety/getPredmetInfo` has several fields (`metodyVyucovaci`, `metodyHodnotici`, `ziskaneZpusobilosti` observed so far) that return a fixed Czech placeholder sentence ("U tohoto předmětu se již používá nový QRAM...") instead of real content once a course has migrated to the newer QRAM system. Treat these as potentially-dead depending on the course.
- `predmety/getPredmetInfo`'s `lang` param (e.g. `en`) translates `nazev`, `nazevDlouhy`, `anotace` and other free-text fields server-side.
- `ng_predmety/searchSimplePredmety` 403s with "refused the requested role" for a ticket with the `ST` (student) role even when `stagUser` is set to that same account's own login — tried both a placeholder value and the real login name, same rejection either way. Untested whether a different role ticket (e.g. `UCIT`) works. Matches its docs' "Negarantováno!" flag; prefer the old `predmety` namespace until this is sorted out.
- `predmety/getPredmetyByFakulta` called with zero filters returns STAG's entire subject catalog (~9,900 rows, ~3.3MB) rather than erroring, unlike `najdiPredmety`'s 500-on-empty-filters. ~0.2s to fetch authenticated; filtering all rows client-side takes single-digit milliseconds, cheap enough to be the actual search implementation (`SearchPredmetyTool` fetches it unfiltered and matches nazev/katedra/zkratka as substrings locally, since `najdiPredmety`'s `nazev` exact-match makes it useless for free-text search). Unlike `najdiPredmety`/`getPredmetInfo`, it 401s anonymous — needs a real STAG token.
- `predmety/getPredmetyByFakulta` rows always populate `maVyuku`, `vyukaZS`, `vyukaLS`, `nabizetPrijezdyEcts`, and `jazyk1` (sparser for `jazyk2`-`jazyk4`) — unlike `najdiPredmety`'s search rows, which leave those null. `semestr`, `pocetStudentu`, and the `aMax`/`bMax`/`cMax`/`aSkut`/`bSkut`/`cSkut` capacity fields are always null on both endpoints.
- `kalendar/getAktualniObdobiInfo`, `kalendar/getHarmonogramRoku`, `kalendar/getKalendarRoku` all answer anonymous callers; `rozvrhy/getRozvrhByStudent` 401s without a ticket.
- Date params take `d.M.yyyy` only: `kalendar/getKalendarRoku`'s `datum` and `rozvrhy/getRozvrhByStudent`'s `datumOd`/`datumDo` both 500 on ISO.
- `kalendar/getHarmonogramRoku`'s `rok` is documented required but defaults to the current academic year when omitted; a bogus year returns `{"harmonogramItem": []}`, not an error.
- `kalendar/getKalendarRoku`'s `typTydne` is per-day, not per-week — week 52 of 2026 runs S,L,S on 21.-23.12.2026. Never derive it from `cisloTydne` parity.
- `kalendar/getKalendarRoku`'s `rozvrhDen` is the timetable weekday, not the real one: 18.5.2027 (a Tuesday) returns `Pá`. On `Sv` (Svátek) and `Rd` (Rektorský den) days the real weekday isn't recoverable from the payload at all; compute it separately (e.g. with Carbon).
- `getHarmonogramRoku` and `getKalendarRoku` can disagree: 22.12.2026 is "Rozvrh je jako v Út sudý týden" (even) in the harmonogram but `typTydne: L` (odd) in the day calendar. Surface both rather than picking one.
- `ciselniky/getCiselnik`'s parameter is `domena` (plus `lang`) — `ciselnikId`/`kod`/`nazevCiselniku` were all wrong, hence the 500s. `ciselniky/getSeznamDomen` lists all 513 domain names; both answer anonymously. A bogus `domena` returns an empty `ciselnik` element with HTTP 200, not an error. `lang=en` is ignored by at least some domains (`STAV_ABSOLVOVANI` stays Czech).
- `rozvrhy/getRozvrhByStudent` requires `osCislo`; omitting it 500s. `help/getStagUserListForActualUser` resolves it (wrapped in `stagUserInfo`), and can return several rows for one account (one per role).
- `rozvrhy/getRozvrhByStudent` with a date range silently omits occurrences that don't happen — no cancelled flag, and no parameter brings them back (`vsechnyAkce`/`vsechnyCasyKonani`, alone or together, don't help). E.g. 10.11.2026 (Rektorský den) returns zero of that week's 10 events, while 11.11.2025 (also Rektorský den) drops only 2 of several.
- `rozvrhy/getRozvrhByStudent`'s `nekonaSe` is not a cancellation flag: observed value `"28.11.2025: Koná se (proběhne v EP120)"` is a positive override, and the structured `mistnost` still said the original room. Format is `d.M.yyyy: <label> (<detail>)`.
- `rozvrhy/getRozvrhByStudent`'s `vsichniUciteleJmenaTituly` looks quoted like `predmety`'s name lists but isn't — it's a plain comma-separated string, so a title with a comma ("Ing. X, Ph.D.") breaks a naive split. Use `vsichniUciteleJmenaTitulySPodily` instead: it's quoted per entry with a trailing workload percentage (`'Name' (100)`), so pull names with `preg_match_all("/'([^']*)'/u", ...)` rather than a quote-comma-quote split, since entries end in `(N)` and don't directly abut the next quote.
- `ng_terminy/getTerminyStatnic` is dead: `p_datum_od` is mandatory and 500s on every format tried (`2026-09-01`, `1.9.2026`, `01.09.2026`, `20260901`, `2026/09/01`, ISO datetime, empty) with `Parameter Class org.joda.time.LocalDate has no constructor...`. No SOAP fallback (`/ws/services/ng_terminy?wsdl` 404s). No other endpoint in the API covers state exams.
- `?_wadl` on any rest2 namespace (`https://stag-ws.zcu.cz/ws/services/rest2/<ns>?_wadl`) returns a WADL with the full response XSD — every field name, type and `minOccurs`. Anonymous, 200 on all 46 namespaces, including ones whose endpoints 401. `?wsdl` on the same path 401s and `/ws/services/<ns>?wsdl` 404s. Use it to get a response shape without live data.
- `podporaVyuky/getStavSP` is dead for student tickets: returns `{"skupiny":[],"bylyOdstranenyNejakeSkupiny":false}` even when passed the `skupIdno` of a group the portal is rendering for that same student at that moment. Ruled out every year/semestr/lang/filter/boolean combination, all three Accept types (json/xml/yaml agree the set is empty server-side), and 2019-2026. Response schema is full of group-admin fields (`skupAdminSkupiny`, `skupAdminSp`, `pocetStudentuSkupiny`), so it's probably scoped to groups you administer. Flagged `Negarantováno!`.
- `podporaVyuky/getStavSP` requires `rokVarianty`, `semestr` and `lang` (500 if any is missing) but validates none of their values — `rokVarianty=abcd` or `semestr=XX` return an empty list, not an error. `rokVarianty` is the starting year (`2026` = 2026/2027); `semestr` accepts `%` for both.
- `podporaVyuky/getStavSP` 403s for a `stagUser` other than the caller's own login, so the identity check works even though the query returns nothing.
- `podporaVyuky/downloadPraceContentForOdevzdejCZ` 401s even with a valid student ticket (odevzdej.cz service account only). `podporaVyuky/exportMetadataForOdevzdejCZ` is absent from the WADL and 500s.
- `soubory` does not cover semestrální práce: no matching type in `getTypySouboru`, and `getSouboryMetadata?osCislo=...` returns `[]`. Submissions live under their own `praceIdno` with no student-reachable download endpoint.
- IS/STAG portal pages are not an API fallback: they're Liferay portlet resource URLs bound to a portal session plus a `_csrf` token, with per-render `pc_windowid`/`pc_phs` handles, and they don't accept STAG WS tickets.
- `znamky`'s 403s are role-gated, not endpoint-gated: `getZnamkyByPredmet` and `getZnamkyByRoakce` refuse an `ST` ticket but work on a `VY` (Vyučující) one, returning whole class rosters (268 and 314 rows on one subject). Confirmed on an account holding both roles — passing `stagUser=<the ST login>` still 403s while the VY login, or no `stagUser` at all, succeeds. So STAG resolves the most capable applicable role when `stagUser` is omitted, and `stagUser` narrows rather than elevates. Nothing in `znamky` is flagged `Negarantováno!`.
- `znamky/getZnamkyByTermin` is dead regardless of role: 500s on every real `termIdno` taken from `terminy/getTerminyZkousek`, with or without `stagUser`, on a VY ticket. Omitting `termIdno` returns an empty list rather than erroring, so it is reachable and simply broken, like `ng_terminy/getTerminyStatnic`.
- `znamky/getZnamkyByPredmet` and `getZnamkyByRoakce` return the identical `hromadne_znamky` row shape as `getZnamkyByStudent` (same keys, same order), just many students on one subject instead of one student on many subjects — the same mapper handles both. `zk_body` was empty across all 268 rows of one subject, so points are per-subject practice rather than universal, and the whole `zppzk_*` block is null on an exam-only subject.
- A `VY` ticket can read grades for a subject it teaches even when a different teacher recorded them (`zk_ucit_idno` pointed at another `ucitIdno` on all 226 graded rows). Read access follows the teaching assignment, not authorship of the grade.
- `znamky/getZnamkyByStudent` 500s with no params, but a foreign or bogus `osCislo` returns an empty list rather than 403 — an empty result is indistinguishable from "wrong student", so resolve identity from the ticket.
- `znamky/getZnamkyByStudent`'s `pracZkr`/`zkrPredm` are exact-match and case-sensitive but honour SQL wildcards: `KIV` and `KI%` both return 17 rows, `KI` and `kiv` return zero. `rok` is the starting year (`2025` = 2025/2026; `2025/2026` returns nothing) and `semestr` accepts `%`.
- `znamky/getZnamkyByStudent` pads its dates (`19.01.2026`), unlike the unpadded `d.M.yyyy` elsewhere in STAG. Its numeric-looking fields split arbitrarily: `zk_tyhoidno`/`zk_hodnidno` are ints, while `rok`, `zk_hodnoceni`, `zk_body` (`"98.00"`), `zk_pokus` and `zk_ucit_idno` are strings. Empty strings appear as often as nulls, sometimes for the same field across two rows.
- `znamky/getZnamkyByStudent`'s `semestr` other than `ZS`/`LS`/`%` (e.g. `XX`) returns an empty list rather than an error, same as a garbage `rok` — validate both client-side rather than trusting an empty result to mean "no grades".
- `znamky/typyHodnoceni` is anonymous and nests every `hodnoceni` with `jeToUspech`, `hodnotaDoPrumeru` and `doPrumeru`, making `vsechnaHodnoceniTypu` and `vsechnaPlatnaHodnoceniTypu` redundant.
- STAG's weighted average counts only numeric-scale (Zp+Zk) subjects and scores an enrolled-but-never-completed one as 4 rather than skipping it. Verified against a printed FAV transcript: 84/41 = 2,05 exactly, where passed-only gives 40/30 = 1,33. Zápočet-only subjects are excluded even when failed. The rule is in the codebook, not hardcoded — each scale carries `nevyplnenoHodnotaDoPrumeru` (4.0 for `1|2|3|4`, null for `S|N`).
- A failed subject that is later retaken and passed appears as two rows and must only be counted once, or it scores both a 4 and its real grade. STAG's transcript draws the same line, listing the still-failed ones under "Nesplněné předměty později neopravené". There is no status code for it: it only exists in the pair of rows, so the full history is needed even to summarise one semester.
- `stavAbsolvovani` resolves against the `STAV_ABSOLVOVANI` domain: 13 codes, not the 3 one account shows. `N` (failed, grade recorded) and `NX` (failed, no grade) are distinct, so never assume a failure lacks a grade. Also covers recognition (`U`/`UP`/`NU`), transfers (`NP`/`NPX`) and deferrals (`O`/`R`).
- `student/getStudentPredmetyAbsolvoval` ignores `osCislo` entirely (its only WADL param is `stagUser`) and always returns the ticket holder's rows — a foreign osCislo or no params at all give the same result. It 401s anonymously and is the only source of `nazevPredmetu` and `pocetKreditu` for a graded subject; its `absolvoval` flag cannot tell a failure from a not-yet-sat subject, which `stavAbsolvovani` can.
- `student/getStudentPredmetyAbsolvoval` wraps its date as `{"value":"19.1.2026"}` unpadded, while `znamky` sends a bare padded `"19.01.2026"` for the same exam.
- `ng_znamky?_wadl` returns 200 but declares zero resources — an empty stub, no new-generation path to prefer.
- `student/getStatistikyRocni` and `student/getStatistikySuma` both 500 flat with a valid ST ticket.

- `help/getStagUserListForActualUserV2` is a strict superset of the non-V2 endpoint: same `stagUserInfo` role rows plus top-level `jmeno`, `prijmeni`, `titulPred`, `titulZa`, `email`. Prefer it; `ResolvesStagIdentity` uses it.
- `help/getStagUserForActualUser` (singular) 403s on a multi-role account — it cannot pick a role. Only the list endpoints work there. Both 401 anonymously; `help/organizaceInfo` is the one anonymous endpoint in the namespace.
- A dual-role account's `stagUserInfo` rows are disjoint: the `VY` row has `ucitIdno` (a real int) and null `osCislo`, the `ST` row the reverse. `ucitIdno` is the only int in the row; everything else is a string.
- `student/getStudentInfo` needs `osCislo` (500 without it) and 403s for a foreign or bogus one — a real identity check, unlike `znamky/getZnamkyByStudent`, which returns an empty list. Its `lang=en` is ignored: `nazevSp` stays Czech. `rocnik`, `stprIdno`, `oborIdnos`, `financovani`, `typSpKey` and `studReferentkaUcitidno` all come back as quoted strings.
- `student/getStudentFull` 403s even for the caller's own `osCislo`. Admin-scoped, not usable from a student or teacher ticket.
- `student/getStudentOsobniUdaje` has no `osCislo` param at all (only `stagUser`) and always returns the ticket holder, ignoring any `osCislo` passed — same quirk as `getStudentPredmetyAbsolvoval`. It carries rodné číslo, home address, phones, date of birth and bank-account fields, so keep it out of MCP output.
- `ucitel/getUcitelInfo?ucitIdno=` answers any authenticated caller including a student, and returns `[]` for an unknown id rather than a 404. 401s anonymously.
- `orion` is not worth wrapping: `getOrionLoginByOsobniCislo` returns `[]` for a student's own number, `getUcitIdnoByOrionLogin` returns `[]` for a non-teacher, and `getOsobniCislaByOrionLogin` (param `login`, not the docs' `orionLogin`) only reproduces `getStudentInfo.userName`. The docs page has the wrong param names for this namespace — read the WADL instead.
- `ciselniky/getCiselnik` wraps a populated list in `ciselnikItem`; the bare `ciselnik` key only shows up on a bogus `domena`.
- Codebooks for `getStudentInfo`'s codes: `stav` → `STAV_STUDENTA` (S/P/N), `formaSp` → `FORMA_OBORU_NEW` (P/K/D). `typSp` (B/N/D) has none — `TYP_STUDIA` classifies the school (1 = Vysoká škola), not the degree. `mistoVyuky`'s `"P"` does not resolve against `MISTO_VYUKY`, whose keys are municipality numbers (554791 = Plzeň).

- `ucitel/getUcitelInfo`'s `zkrBudovy` and `cisloMistnosti` are sparse, not dead (earlier note here said "always null" — wrong, it sampled a department that has none). Fill rate is per-department: KIV 39/316, UTS 6/10, FPR 7/249, KMA 1/98, KKY 0/128. When filled they agree exactly with `vizitka/getVizitkaByUcitidno`'s `tsLinky.linky[].budova`/`mistnost` (both `UC`/`304` for ucitIdno 17098). `vizitka` is still the better source, since its room rides on the phone-line row that someone actually maintains.
- `ucitel/getUcitelInfo`'s and `getUciteleKatedry`'s `telefon` is unvalidated free text, not a phone number. Across FAV's 147 filled values: 130 are 4-digit internal extensions, 11 are full 9-digit numbers, 4 are 11-char (`05/41142807`, `602 510 598`), plus junk like `UN325` (a room) and a 16-char `+420 549 496 831` (a Brno landline, not ZČU). A 4-digit value is not reliably that person's extension either (one row reads `9159` while their card lists 2304 and 2335). Never prefix or normalise it. Study-office staff (`studReferentkaTelefon`) do hold proper full numbers, since the study department maintains those rows rather than the person.
- `vizitka/getVizitkaByUcitidno` takes `ucitidno` (all lowercase, unlike `ucitIdno` everywhere else) and returns `[]` for an unknown id. `getVizitka` takes the Orion login (`sutnerov`), *not* the STAG login (`SUTNEROVA`), which returns `[]`. Both answer anonymously; `vizitka/telefonniSeznamZCU` does not and 401s even with a valid `ST` ticket.
- `vizitka`'s `tsLinky.linky` is one row per phone line with the building and room repeated on each, so a person with two lines in one office looks like two offices until deduped. Its `telefon`/`fax` fields are `A`/`N` flags, not numbers; `cislo` is the extension and `mobil` was null on every row sampled.
- A `vizitka`'s `uredniHodiny` is null exactly when `info.showKonzultace` is `N`, which for study-office staff is near-universal (null for both test referentky). Treat STAG's úřední hodiny as unmaintained rather than authoritative: studijní oddělení are required to keep them and publish them on the faculty website, which is where they are actually read. `StudyAdvisorTool` deliberately returns none and points at the faculty site instead, derived from the person's email domain (`sutnerov@fav.zcu.cz` → fav.zcu.cz). Its `den` is numeric `1`-`7` (Monday first) and `tyden` is *lowercase* `k`/`s`/`l`/`j`, unlike the uppercase `TYDEN` číselník, if a future tool does read them. `denS`/`tydenS` carry Czech labels here but are null in `getUredniHodinyPracoviste`, which is otherwise the same row shape.
- `orion/getUcitIdnoByOrionLogin` returns a bare integer, not an object. `StagClient::send()` declares an `array` return, so it raises a `TypeError` rather than a `StagException` — any tool wrapping a scalar-returning endpoint needs the client widened first.
- `users/getOsoba` and `ucitel/selectUcitelOsobniUdaje` 403 for an `ST` ticket; `cro_ucitele/selectUcitele` 500s. None is a route to staff contact details.

- `student/getStudiaByCisloKarty` is role-gated the way `znamky/getZnamkyByPredmet` is: an `ST`-only ticket 403s ("Pristup k temto datum neni povolen kvuli nastaveni systemu"), a ticket holding `VY` returns 200 with `{"studentShort":[]}` for an unknown card. It has no `stagUser` param at all (only `cisloKarty`), so the role cannot be narrowed or steered. `cisloKarty=` empty returns HTTP 204 with an empty body; omitting it 500s. Anonymous is 401. Untested positively, since nothing in the API exposes a card number to look one up with.
- `soubory/getSouboryMetadata` needs one of `adipIdno`/`stpsIdno`/`stzaIdno`/`osCislo` (500 otherwise, and the message lists exactly those four). `tysoIdno` is a filter on top, never a standalone key.
- `soubory/getSouboryMetadata?osCislo=` answers **anonymously** and for any authenticated account, returning another student's file list unfiltered — rows carry the filename, size, upload date, `osCislo` and a ready-made `webserviceDownloadURL`. Downloading is narrower: `getSouborContent` 500s ("Pristup k souboru odepren") anonymously but returns the file to an unrelated student's `ST` ticket. Observed on `potvrzeni_o_studiu-*.pdf` rows whose `zpristupnitVerejnosti` is `A`. Treat cross-account reads as reachable, not as protected by STAG.
- `soubory/getSouborContent` and `getSouborContentAuth` return the file base64-encoded inside a JSON string (`"JVBERi0xLjQ..."`) under `Accept: application/json`, not binary — decode before writing. No `Content-Disposition`; the name comes from the metadata row's `nazev`.
- `soubory/getSouborOpravneni` and `getSouborContentAuth` reject a multi-role ticket outright ("Volanou službu smí spustit pouze uživatelé, kteří mají jednu z následujících rolí ... <jakákoliv IS/STAG role>") unless `stagUser` names one login. Here `stagUser` is mandatory disambiguation, not the optional narrowing it is elsewhere. `getSouboryMetadata`, `getSouborMetadata` and `getSouborContent` take the same multi-role ticket fine.
- `soubory/getTypySouboru` is anonymous and returns all 157 types regardless of role; `souborProKoho` resolves against the `SOUBOR_PRO_KOHO` domain (`1` student/os_cislo, `2` VŠKP/adipidno, `3` žádost/stzaidno, `4` příjezd/stpsidno, `5` e-přihláška, `6` uchazeč, `7` téma VŠKP, `8` mobilita, `9` výjezd, `A` návrh místa praxe, `K` klauzurní práce, `O` odvolání, `P` praxe). Only the 7 `souborProKoho=1` types are reachable by `osCislo`.
- `soubory` metadata dates come wrapped as `{"value":"16.9.2025 14:02"}` (`souborLDU`, `dateOfInsert`, `validaceDatum`), unpadded `d.M.yyyy H:mm`, same wrapper as `student/getStudentPredmetyAbsolvoval`.
- A `soubory` row's filename can name a different `osCislo` than the row it hangs off (`elektronicke_potvrzeni_o_studiu-r21m0016p.pdf` under `osCislo: R21P0002P`) — leftovers from an earlier study of the same person. Don't parse identity out of `nazev`.

- `vizitka/getUredniHodinyPracoviste` is anonymous, takes `pracoviste` (mandatory, 500 without it) and accepts a faculty *or* a department code (`FAV` 178 rows, `KIV` 87, `KMA` 54, `FPR` 60, `CIV` 15). `pracoviste=` empty returns all 996 rows university-wide; a bogus code returns 0 rows, not an error. Rows wrap in `wsUredniHodinaItem`.
- `vizitka/getUredniHodinyPracoviste` returns one row per slot, not per person (FAV: 178 rows / 120 logins, 57 people with two or more). `login` is the Orion login, matching `vizitka/getVizitka` and not the STAG login. `denS`/`tydenS` are null on every row, so `den` (`1`-`7`) and `tyden` (lowercase `k`/`s`/`l`/`j`) must be mapped client-side. `tyden` is `k` on 970 of 996 rows.
- `vizitka/getUredniHodinyPracoviste`'s `hodinaOd`/`hodinaDo` are free text, not times: 437 of ~1992 values across the university fail `H:mm` (`11.00`, `13.55`, bare `8`, bare `12`), 6 rows have `hodinaDo <= hodinaOd`, and `0:00`-`0:01` is used as a "mail me and we'll arrange it" sentinel. Parse defensively or pass through verbatim.
- `vizitka/getUredniHodinyPracoviste`'s `poznamka` (filled on 834/996) is where the room actually lives: 386 are a bare room code (`UN403`, `UC357`, `[EK405]`, `UK 413`, no consistent format), the rest free text mixing rooms, semesters, phone numbers and Skype handles. It is the same unmaintained data `StudyAdvisorTool` deliberately refuses to serve — several rows still scope themselves to past semesters.

- A third of the university writes the office hours off in their own `poznamka`: 218 of 664 people (FAV 43/120, FPR 26/49) say some form of mail/domluva/dohoda/zavolat/Teams instead. Matched against lived experience — teachers list hours and then tell students to message them regardless — so `getUredniHodinyPracoviste` is recorded, not observed, behaviour. Deliberately not wrapped in a tool; see the todo entry.

- `programy` splits cleanly by auth: the catalogue endpoints (`getStudijniProgramy`, `getStudijniProgramInfo`, `getOborInfo`, `getPlanyOboru`, `getSegmentyPlanu`, `getBlokyPlanu`, `getBlokInfo`) answer anonymously, while `getPlanyStudenta` 401s anonymously and **403s for a foreign `osCislo`** — a real identity check, unlike `soubory` and `znamky/getZnamkyByStudent`. No `stagUser` param anywhere in the namespace.
- `programy/getStudijniProgramy` with zero filters returns all 514 programmes university-wide rather than erroring (`fakulta=FAV, pouzePlatne=true` narrows to 53), same shape as `predmety/getPredmetyByFakulta`.
- The `programy` tree is program (`stprIdno`) → obor (`oborIdno`) → plán (`stplIdno`) → segment (`sespIdno`) → blok (`blokIdno`). `getPlanyStudenta` is the only entry point that starts from a student, and returned exactly one `planInfo` for a first-year.
- `programy/getBlokInfo` and `getBlokyPlanu` return **no subject list** — a blok is only its credit rule (`statut` A/B/C, `minKred`, `minPocetPredmetu`). The subjects that satisfy it live in `vsp/getStudijniPlan`, so `programy` alone cannot answer "what do I still need to take".
- `programy/getStudijniProgramInfo` is 87 fields (40 filled, ~5 KB per programme) of accreditation and marketing prose: `profilAbsolventaCz/An`, `moznePracovniPoziceCz/An`, `pozadavkyNaPrijeti*`, `akreditace*`. `getOborInfo` is 59 fields but only 18 filled on a post-novela programme, since the obor-level prose moved to the programme. Pick fields deliberately rather than passing either through.
- `vsp/getStudijniPlan?stplIdno=` is anonymous and is the real study-plan payload (276 KB for one bachelor plan): segments → `bloky` → `predmety`, each subject carrying `doporucenyRocnik`, `doporucenySemestr`, `kredity`, `rozsah`, `typZk`, plus `podminujiciPredmety`, `vyloucenePredmety`, `nahrazovanePredmety` and `doporucenePredmety`. Free text comes as `{valueCs, valueEn}` pairs rather than a `lang` param.
- `vsp` payloads carry presentation HTML in the data: `zkratkaProZobrazeni` is `"KIV<span>/</span>BPSWI"`, and blok rows duplicate `statut` into `statutA`/`statutB`/`statutC`/`statutX` booleans. Strip the markup, read `pracZkr`/`zkrPredm` instead.
- `vsp/getStudent` is **broken as JSON**: `StudentVRoce["student"]` points back at `Student["rokyStudia"]`, so Jackson recurses until it gives up and the 104 KB body ends mid-structure with the cycle trace appended (`Infinite recursion (StackOverflowError)`). It parses at no `json_decode` depth — 512 hits max depth, higher depths hit a syntax error, because the bytes really are truncated. `Accept: application/xml` returns a clean 31 KB document instead. First endpoint found that needs XML.

- `vsp` is two endpoints only. `getStudijniPlan?stplIdno=` is anonymous; `getStudent?osCislo=` 401s anonymously, and its `osCislo` is a **lie** — it is mandatory (500 without it) but ignored, so a foreign or bogus value returns the ticket holder byte-for-byte, same as `student/getStudentPredmetyAbsolvoval` and `getStudentOsobniUdaje`. Resolve identity from the ticket, never report the requested number back.
- `vsp/getStudent` shape: `vspStudent` (program totals: `kredityNutnoZiskatProgram`, `kredityZiskaneCelkem`, `kredityUznaneCelkem`) → `rokyStudia[]` (one `studentVRoce` per academic year, each with its own `stplIdno`, so the plan version changes year to year) → `obory[]` → `predmety[]` of `predmetStudenta`. `kredityZbyvaAbsolvovat` is a programme-level figure copied onto every year, not a per-year remainder (138.0 on both of a first-year's rows, 35.0 on all six of a sixth-year's). `limitKredituRok` was absent on every row.
- `vsp`'s `predmetStudenta` is the per-subject progress row: `statut` (A/B/C), `stavAbsolvovani`, `znamkaHodnoceni`, `znamkaPokus`, `uspesneAbsolvovany`, `uznano`, `praveStudovan`, `zapsanProPristiRok`, `odlozeno`, `semestr`, `kredity`, plus the embedded `predmetVarianta`. A retake is two rows in different `rokyStudia` years (failed `NX` in 2025, `S` and `praveStudovan` in 2026), which is more legible than the `znamky` pairing. It carries **no subject name** — only `pracZkr`/`zkrPredm` — so names must come from the plan or `predmety/getPredmetInfo`. `typPredmetu` is an enum: `ZNAMKY`, `JEDZNAMKY`, `STUDENTEM_VYBRANE_PREDMETY`.
- `vsp/getStudijniPlan` shape: plan → `skupinySegmentu[]` → `segmenty[]` → `bloky[]` → `predmety[]`, each subject an embedded `predmetVarianta` with `nazev {valueCs, valueEn}`, `kredity`, `rozsah`, `typZk`, `doporucenyRocnik`, `doporucenySemestr` and `vyznamPredmetu`. 114 subjects across 10 blocks on one bachelor plan. This is the only place the subjects that satisfy a blok are listed; `programy/getBlokInfo` gives the credit rule and nothing else.
- `vsp/getStudijniPlan`'s `podminujiciPredmety` comes back empty at ZČU — 0 of 114 subjects on two FAV plans and 0 of 50 on two FPR plans, across 2021-2026. The field works; ZČU abolished prerequisites some years ago, so there is nothing to return. Treat an empty list as "this school has none" rather than as a data error, and keep the mapping in place in case they come back or another STAG school populates it. `doporucenePredmety` (23/114) is the closest live equivalent, a soft "take this first" link (KIV/ADT → KIV/PPA). `vyloucenePredmety` (19/114) and `nahrazovanePredmety` (9/114) are populated.
- `vsp/getStudijniPlan`'s `pocetSemestru` is `0` on every plan sampled, while `programy/getPlanInfo` returns the real 6 for the same `stplIdno`. Take it from `programy`. `poznamkaVerejna` is the literal placeholder `"Poznámka k plánu"` in both languages, and `nazev.valueEn` falls back to the Czech string on plans nobody translated.
- The same subject can legitimately appear twice inside one `vsp` blok with different `id` and identical everything else (`UTS/TV` twice at 1 credit against a 2-credit minimum — you take it two semesters), and once in two different bloky (`KIV/PRO` in both Skupina 2 and Skupina 6, counting for either). Deduplicating by `pracZkr`/`zkrPredm` loses the first case; summing blindly double-counts the second.
- Joining `vsp/getStudijniPlan` with `vsp/getStudent` produces a working degree audit: all 23 of one student's enrolled and passed subjects matched a block in the current plan, giving per-block "need 132 credits over 27 subjects, have 31 over 7, 45 in progress, these 11 still required". That join is the point of the namespace — neither half is worth much alone.
- `vyznamPredmetu` resolves against the `VYZNAM_PREDMETU` domain: `B` běžný, `P` profilující základ, `T` základní teoretický profilujícího základu. `STATUT_PREDMETU` and `TYP_PREDMETU` are not domains (0 items).

- The `vsp/getStudent` XML is plain enough for SimpleXML: 31 KB, max depth 7, zero attributes, one namespace on the root only, no mixed content. Do **not** decode it with `json_decode(json_encode($sx), true)` — a repeated element collapses to an object when the document happens to hold exactly one of it, so `rokyStudia` is a list for a second-year and an object for a first-year, and `obory` is an object on every row sampled. Iterate SimpleXML directly (`foreach` and `count()` behave the same for 1 and for many) and cast leaves explicitly: every value arrives as a string, so the string `"false"` from `uspesneAbsolvovany` is truthy in PHP and needs `filter_var(..., FILTER_VALIDATE_BOOL)`.

## Writing notes
When adding to the file, add a new bullet point under `## Notes` with the minimum needed information, don't write unnecessary prose. Short and sweet beats verbose and unreadable.

- `ucitel` docs lie about anonymous access: they mark all read endpoints "can be called without login", but `najdiUcitelePodleJmena`, `getUcitelInfo` and `getUciteleKatedry` all 401. Genuinely anonymous: `getUcitelePredmetu`, `getUciteleRoakce`, `getUcitIdnoByStagLogin`, `getGarant_ProgramOborByUcitIdno`, `getGarant_ProgramOborByRC`. The four `*UcitelOsobniUdaje` endpoints are `AD` role only (`selectUcitelOsobniUdaje` 403s for `ST`), and `ucitelOsobniUdajeType` carries `rodCislo`/`datumNarozeni`/`pohlavi` — never wrap them. `ng_ucitel?_wadl` is an empty stub like `ng_znamky`, zero resources.
- `ucitel/najdiUcitelePodleJmena` is the namespace's only free-text search and it is **case- and diacritics-insensitive with SQL wildcards**, unlike every other STAG filter found so far (`znamky`'s `pracZkr` is exact and case-sensitive, `predmety/najdiPredmety`'s `nazev` is an exact full-title match). `herout`, `HEROUT` and `Ježek`/`Jezek` all match; `Her` alone returns 0 but `Her%` returns 30 and `%a%` returns 7764 rows with no cap. It needs at least one literal character: zero params, `prijmeni=%` and `prijmeni=_%` all 500. Rows are the bare 7-field `ucitelType` (no email/department) — pair it with `getUcitelInfo` for contact details.
- `ucitel/getUciteleKatedry`'s `jenAktualni` and `zobrazitExternisty` are **presence-only booleans**: the value is ignored, `A`, `N`, `xyz` and `` all behave identically, only sending the key at all matters. Both read inverted to their names. KIV: neither = 316 (`platnost=A`, employees and externals); `jenAktualni` = 601 (adds `platnost=N` history); `zobrazitExternisty` = 103 (`zamestnanec=A` only, i.e. drops externals); both = 278. So `platnost` looks like a dead column on the default call only because the default already filters on it.
- `ucitel/getUciteleKatedry` rows can name a *different* `katedra` than the one requested (an NTIS row with `pracovisteDalsi: KIV` comes back for `katedra=KIV`) — the filter matches either workplace. `email` is far from universal (KIV 116/316, KKY 100/128) and `phdSkolitel` was `N` on all 801 rows sampled. A bogus or empty `katedra` returns an empty list, not an error.
- `ucitel/getUcitelePredmetu` returns two different row kinds keyed by `vazbaNaPredmet`, and `typAkce` means something different in each. On `ra` (rozvrhová akce) rows it is a real `TYP_AKCE` code (`Př`/`Cv`/`Se`). On `pr` (předmět) rows it is a **4-char A/N flag string** — `AAAN`, `NNAN`, `NANN` — positionally garant / přednášející / cvičící / seminárista. Verified positions 1-3 against `predmety/getPredmetInfo`'s `garantiUcitIdno`, `prednasejici` and `cvicici` on four subjects; position 4 is inferred, since `seminariciUcitIdno` is empty on every subject sampled. There is no `VAZBA_NA_PREDMET` číselník (0 items), and `TYP_AKCE` only covers the `ra` half.
- `ucitel/getUcitelePredmetu` is largely redundant with `predmety/getPredmetInfo`, which already carries `garantiUcitIdno`, `prednasejiciUcitIdno`, `cviciciUcitIdno`, `seminariciUcitIdno` and `examinatoriUcitIdno`. What it adds is ids and names in one row, plus the `ra` rows. Its `rok` is the starting year and defaults to the current one; a year with no data returns rows only for the garant rather than erroring (KIV/PPA1: 20 rows in 2020, 1 from 2023 on), so a thin result means "not filled for that year", not "one teacher".
- `ucitel/getUcitIdnoByStagLogin` returns a **bare integer** for a hit and `[]` for a miss, so the type flips by outcome — same `StagClient::send(): Return value must be of type array` TypeError as `orion/getUcitIdnoByOrionLogin`. It takes the STAG login (`HEROUT`), case-insensitively, unlike `vizitka/getVizitka` which wants the Orion login.
- `ucitel/getUciteleRoakce` validates nothing: `roakIdno=1` returns a real person. Rows are `ucitelType` plus `podilNaVyuce` (an int percentage) and no contact fields. It is the only clean way to get `ucitIdno` for one timetable event, since `rozvrhy/getRozvrhByStudent` only gives names as text.
- `ucitel/selectUciteleTerminStatistikaPoctuStudentu` is dead from outside: 500 "Service is not allowed for caller's IP address (client IP: ...)" both anonymously and with a valid ticket. IP-allowlisted, not role-gated — a failure mode not seen anywhere else in the API.
- `ucitel/getGarant_ProgramOborByRC` called with **no `rc` at all** dumps the whole guarantor table (1060 rows, 329 distinct rodná čísla, 11 faculties, 257 KB) to **unauthenticated** callers, `rodné číslo` in the clear as `osoba_Garant_RC`. Its `return` type is also the one place in the namespace using `snake_Case` keys and numeric faculty codes (`23900`) instead of `FAV`. Do not wrap it; the data is stale (`platnost: N` throughout, pre-2011 programme codes) and the id it keys on is a national identifier. Prefer `getGarant_ProgramOborByUcitIdno`, which is the same question asked with a STAG id and returns clean `GarantProgramOborBean2Type` rows.
- `ucitel/getGarant_ProgramOborByUcitIdno`'s `typ` is `P` (programme guarantor, `oborIdno: 0`) or `O` (specialisation guarantor, real `oborIdno`); one person commonly holds both for the same `stprIdno`. No číselník backs it (`TYP_GARANTA` and `GARANT` are both 0 items). `rok` defaults to the current year and a pre-history year returns an empty list; an unknown `ucitIdno` returns `[]`, like `getUcitelInfo`.
