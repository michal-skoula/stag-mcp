## Notes
- `ng_*` namespaces mean "new generation", these are more modern versions of old API namespaces. When available always use these instead of the old ones. HOWEVER, they don't always have 100% feature parity with the old versions, so sometimes it might be needed to call from both the ng and old namespaces.
- some endpoints are noted as being `Negarantováno!` in the docs, meaning they are volatile and subject to change or be removed. These should probably get their own trait getting error messages like "This tool calls a volatile endpoint that isn't guaranteed". If there are multiple endpoints that do the same thing or overlap, prefer ones which aren't unstable.
- `getBudovy` answers anonymous callers; `getMistnostiInfo` in the same namespace returns 401 without a token even though the docs list it as "probably without the need to log in" for both.
- `mistnost/getBudovy` wraps its list in `items`; `mistnost/getMistnostiInfo` wraps its list in `mistnostInfo`. The wrapper key is per-endpoint, not a namespace-wide convention.
- `mistnost/getMistnostiInfo` (2411 rows, unfiltered) always returns null for `provozDo`, `serial`, `urlMistnost`, `identifikatorBudova`; `identifikatorMistnost` and `dvereCislo` are null in all but one row. `typCiselne` duplicates `typ` as a numeric code. Treat these as dead/near-dead columns.
- `mistnost/getBudovy` `provozOd`/`provozDo` data has quality issues, some rows show `provozOd` after `provozDo` (e.g. zkrBudovy A2: provozOd 4.7.2026, provozDo 1.1.2026). Don't assume the range is well-formed.
- `mistnost/getBudovy`'s `gpsBudovaX`/`gpsBudovaY` are longitude/latitude (X=lon, Y=lat). Its `gpsAdresniMistoX`/`gpsAdresniMistoY` are the reverse (X=lat, Y=lon) and redundant with the budova pair. `mistnost/getMistnostiInfo`'s `budovaGPSX`/`budovaGPSY` follow the `gpsBudova*` convention (X=lon, Y=lat). Map explicitly per field name, don't assume X/Y line up the same way across fields.
- `predmety/najdiPredmety` and `predmety/getPredmetInfo` both answer anonymous callers, like `mistnost/getBudovy` (not like `getMistnostiInfo`).
- `predmety/najdiPredmety` wraps its list in `predmetKatedry`. Calling it with zero filters returns HTTP 500, not an empty list or 400 — always send at least one filter.
- `predmety/najdiPredmety`'s `nazev` param is an exact match on the full course title, not a substring search, unlike `GetBudovyTool`'s address filter. A partial title returns zero rows.
- `predmety/najdiPredmety` rows only ever populate `katedra`, `zkratka`, `rok`, `nazev` — every other field (`semestr`, `vyukaZS`, `pocetStudentu`, the `aMax`/`bMax`/`cMax`/`aSkut`/`bSkut`/`cSkut` capacity fields, etc.) is always null. Fetch `getPredmetInfo` for real data.
- `predmety/getPredmetInfo` for an unknown katedra/zkratka combo returns `[]` (empty array), not a 404 or an error — check for that shape rather than assuming an object comes back.
- `predmety/getPredmetInfo` has several fields (`metodyVyucovaci`, `metodyHodnotici`, `ziskaneZpusobilosti` observed so far) that return a fixed Czech placeholder sentence ("U tohoto předmětu se již používá nový QRAM...") instead of real content once a course has migrated to the newer QRAM system. Treat these as potentially-dead depending on the course.
- `predmety/getPredmetInfo`'s `lang` param (e.g. `en`) translates `nazev`, `nazevDlouhy`, `anotace` and other free-text fields server-side.
- `ng_predmety/searchSimplePredmety` 403s with "refused the requested role" for a ticket with the `ST` (student) role even when `stagUser` is set to that same account's own login — tried both a placeholder value and the real login name, same rejection either way. Untested whether a different role ticket (e.g. `UCIT`) works. Matches its docs' "Negarantováno!" flag; prefer the old `predmety` namespace until this is sorted out.
- `predmety/getPredmetyByFakulta` called with zero filters returns STAG's entire subject catalog (~9,900 rows, ~3.3MB) rather than erroring, unlike `najdiPredmety`'s 500-on-empty-filters. ~0.2s to fetch authenticated; filtering all rows client-side takes single-digit milliseconds, cheap enough to be the actual search implementation (`SearchPredmetyTool` fetches it unfiltered and matches nazev/katedra/zkratka as substrings locally, since `najdiPredmety`'s `nazev` exact-match makes it useless for free-text search). Unlike `najdiPredmety`/`getPredmetInfo`, it 401s anonymous — needs a real STAG token.
- `predmety/getPredmetyByFakulta` rows always populate `maVyuku`, `vyukaZS`, `vyukaLS`, `nabizetPrijezdyEcts`, and `jazyk1` (sparser for `jazyk2`-`jazyk4`) — unlike `najdiPredmety`'s search rows, which leave those null. `semestr`, `pocetStudentu`, and the `aMax`/`bMax`/`cMax`/`aSkut`/`bSkut`/`cSkut` capacity fields are always null on both endpoints.
- `kalendar/getAktualniObdobiInfo`, `kalendar/getHarmonogramRoku`, `kalendar/getKalendarRoku` all answer anonymous callers; `rozvrhy/getRozvrhByStudent` 401s without a ticket.
- Date params take `d.M.yyyy` only: `kalendar/getKalendarRoku`'s `datum` and `rozvrhy/getRozvrhByStudent`'s `datumOd`/`datumDo` both 500 on ISO.
- `kalendar/getHarmonogramRoku`'s `rok` is documented required but defaults to the current academic year when omitted; a bogus year returns `{"harmonogramItem": []}`, not an error.
- `kalendar/getKalendarRoku`'s `typTydne` is per-day, not per-week — week 52 of 2026 runs S,L,S on 21.-23.12.2026. Never derive it from `cisloTydne` parity.
- `kalendar/getKalendarRoku`'s `rozvrhDen` is the timetable weekday, not the real one: 18.5.2027 (a Tuesday) returns `Pá`. On `Sv` (Svátek) and `Rd` (Rektorský den) days the real weekday isn't recoverable from the payload at all; compute it separately (e.g. with Carbon).
- `getHarmonogramRoku` and `getKalendarRoku` can disagree: 22.12.2026 is "Rozvrh je jako v Út sudý týden" (even) in the harmonogram but `typTydne: L` (odd) in the day calendar. Surface both rather than picking one.
- `ciselniky/getCiselnik`'s parameter is `domena` (plus `lang`) — `ciselnikId`/`kod`/`nazevCiselniku` were all wrong, hence the 500s. `ciselniky/getSeznamDomen` lists all 513 domain names; both answer anonymously. A bogus `domena` returns an empty `ciselnik` element with HTTP 200, not an error. `lang=en` is ignored by at least some domains (`STAV_ABSOLVOVANI` stays Czech).
- `rozvrhy/getRozvrhByStudent` requires `osCislo`; omitting it 500s. `help/getStagUserListForActualUser` resolves it (wrapped in `stagUserInfo`), and can return several rows for one account (one per role).
- `rozvrhy/getRozvrhByStudent` with a date range silently omits occurrences that don't happen — no cancelled flag, and no parameter brings them back (`vsechnyAkce`/`vsechnyCasyKonani`, alone or together, don't help). E.g. 10.11.2026 (Rektorský den) returns zero of that week's 10 events, while 11.11.2025 (also Rektorský den) drops only 2 of several.
- `rozvrhy/getRozvrhByStudent`'s `nekonaSe` is not a cancellation flag: observed value `"28.11.2025: Koná se (proběhne v EP120)"` is a positive override, and the structured `mistnost` still said the original room. Format is `d.M.yyyy: <label> (<detail>)`.
- `rozvrhy/getRozvrhByStudent`'s `vsichniUciteleJmenaTituly` looks quoted like `predmety`'s name lists but isn't — it's a plain comma-separated string, so a title with a comma ("Ing. X, Ph.D.") breaks a naive split. Use `vsichniUciteleJmenaTitulySPodily` instead: it's quoted per entry with a trailing workload percentage (`'Name' (100)`), so pull names with `preg_match_all("/'([^']*)'/u", ...)` rather than a quote-comma-quote split, since entries end in `(N)` and don't directly abut the next quote.
- `ng_terminy/getTerminyStatnic` is dead: `p_datum_od` is mandatory and 500s on every format tried (`2026-09-01`, `1.9.2026`, `01.09.2026`, `20260901`, `2026/09/01`, ISO datetime, empty) with `Parameter Class org.joda.time.LocalDate has no constructor...`. No SOAP fallback (`/ws/services/ng_terminy?wsdl` 404s). No other endpoint in the API covers state exams.
- `?_wadl` on any rest2 namespace (`https://stag-ws.zcu.cz/ws/services/rest2/<ns>?_wadl`) returns a WADL with the full response XSD — every field name, type and `minOccurs`. Anonymous, 200 on all 46 namespaces, including ones whose endpoints 401. `?wsdl` on the same path 401s and `/ws/services/<ns>?wsdl` 404s. Use it to get a response shape without live data.
- `podporaVyuky/getStavSP` is dead for student tickets: returns `{"skupiny":[],"bylyOdstranenyNejakeSkupiny":false}` even when passed the `skupIdno` of a group the portal is rendering for that same student at that moment. Ruled out every year/semestr/lang/filter/boolean combination, all three Accept types (json/xml/yaml agree the set is empty server-side), and 2019-2026. Response schema is full of group-admin fields (`skupAdminSkupiny`, `skupAdminSp`, `pocetStudentuSkupiny`), so it's probably scoped to groups you administer. Flagged `Negarantováno!`.
- `podporaVyuky/getStavSP` requires `rokVarianty`, `semestr` and `lang` (500 if any is missing) but validates none of their values — `rokVarianty=abcd` or `semestr=XX` return an empty list, not an error. `rokVarianty` is the starting year (`2026` = 2026/2027); `semestr` accepts `%` for both.
- `podporaVyuky/getStavSP` 403s for a `stagUser` other than the caller's own login, so the identity check works even though the query returns nothing.
- `podporaVyuky/downloadPraceContentForOdevzdejCZ` 401s even with a valid student ticket (odevzdej.cz service account only). `podporaVyuky/exportMetadataForOdevzdejCZ` is absent from the WADL and 500s.
- `soubory` does not cover semestrální práce: no matching type in `getTypySouboru`, and `getSouboryMetadata?osCislo=...` returns `[]`. Submissions live under their own `praceIdno` with no student-reachable download endpoint.
- IS/STAG portal pages are not an API fallback: they're Liferay portlet resource URLs bound to a portal session plus a `_csrf` token, with per-render `pc_windowid`/`pc_phs` handles, and they don't accept STAG WS tickets.
- `znamky`'s 403s are role-gated, not endpoint-gated: `getZnamkyByPredmet` and `getZnamkyByRoakce` refuse an `ST` ticket but work on a `VY` (Vyučující) one, returning whole class rosters (268 and 314 rows on one subject). Confirmed on an account holding both roles — passing `stagUser=<the ST login>` still 403s while the VY login, or no `stagUser` at all, succeeds. So STAG resolves the most capable applicable role when `stagUser` is omitted, and `stagUser` narrows rather than elevates. Nothing in `znamky` is flagged `Negarantováno!`.
- `znamky/getZnamkyByTermin` is dead regardless of role: 500s on every real `termIdno` taken from `terminy/getTerminyZkousek`, with or without `stagUser`, on a VY ticket. Omitting `termIdno` returns an empty list rather than erroring, so it is reachable and simply broken, like `ng_terminy/getTerminyStatnic`.
- `znamky/getZnamkyByPredmet` and `getZnamkyByRoakce` return the identical `hromadne_znamky` row shape as `getZnamkyByStudent` (same keys, same order), just many students on one subject instead of one student on many subjects — the same mapper handles both. `zk_body` was empty across all 268 rows of one subject, so points are per-subject practice rather than universal, and the whole `zppzk_*` block is null on an exam-only subject.
- A `VY` ticket can read grades for a subject it teaches even when a different teacher recorded them (`zk_ucit_idno` pointed at another `ucitIdno` on all 226 graded rows). Read access follows the teaching assignment, not authorship of the grade.
- `znamky/getZnamkyByStudent` 500s with no params, but a foreign or bogus `osCislo` returns an empty list rather than 403 — an empty result is indistinguishable from "wrong student", so resolve identity from the ticket.
- `znamky/getZnamkyByStudent`'s `pracZkr`/`zkrPredm` are exact-match and case-sensitive but honour SQL wildcards: `KIV` and `KI%` both return 17 rows, `KI` and `kiv` return zero. `rok` is the starting year (`2025` = 2025/2026; `2025/2026` returns nothing) and `semestr` accepts `%`.
- `znamky/getZnamkyByStudent` pads its dates (`19.01.2026`), unlike the unpadded `d.M.yyyy` elsewhere in STAG. Its numeric-looking fields split arbitrarily: `zk_tyhoidno`/`zk_hodnidno` are ints, while `rok`, `zk_hodnoceni`, `zk_body` (`"98.00"`), `zk_pokus` and `zk_ucit_idno` are strings. Empty strings appear as often as nulls, sometimes for the same field across two rows.
- `znamky/getZnamkyByStudent`'s `semestr` other than `ZS`/`LS`/`%` (e.g. `XX`) returns an empty list rather than an error, same as a garbage `rok` — validate both client-side rather than trusting an empty result to mean "no grades".
- `znamky/typyHodnoceni` is anonymous and nests every `hodnoceni` with `jeToUspech`, `hodnotaDoPrumeru` and `doPrumeru`, making `vsechnaHodnoceniTypu` and `vsechnaPlatnaHodnoceniTypu` redundant.
- STAG's weighted average counts only numeric-scale (Zp+Zk) subjects and scores an enrolled-but-never-completed one as 4 rather than skipping it. Verified against a printed FAV transcript: 84/41 = 2,05 exactly, where passed-only gives 40/30 = 1,33. Zápočet-only subjects are excluded even when failed. The rule is in the codebook, not hardcoded — each scale carries `nevyplnenoHodnotaDoPrumeru` (4.0 for `1|2|3|4`, null for `S|N`).
- A failed subject that is later retaken and passed appears as two rows and must only be counted once, or it scores both a 4 and its real grade. STAG's transcript draws the same line, listing the still-failed ones under "Nesplněné předměty později neopravené". There is no status code for it: it only exists in the pair of rows, so the full history is needed even to summarise one semester.
- `stavAbsolvovani` resolves against the `STAV_ABSOLVOVANI` domain: 13 codes, not the 3 one account shows. `N` (failed, grade recorded) and `NX` (failed, no grade) are distinct, so never assume a failure lacks a grade. Also covers recognition (`U`/`UP`/`NU`), transfers (`NP`/`NPX`) and deferrals (`O`/`R`).
- `student/getStudentPredmetyAbsolvoval` ignores `osCislo` entirely (its only WADL param is `stagUser`) and always returns the ticket holder's rows — a foreign osCislo or no params at all give the same result. It 401s anonymously and is the only source of `nazevPredmetu` and `pocetKreditu` for a graded subject; its `absolvoval` flag cannot tell a failure from a not-yet-sat subject, which `stavAbsolvovani` can.
- `student/getStudentPredmetyAbsolvoval` wraps its date as `{"value":"19.1.2026"}` unpadded, while `znamky` sends a bare padded `"19.01.2026"` for the same exam.
- `ng_znamky?_wadl` returns 200 but declares zero resources — an empty stub, no new-generation path to prefer.
- `student/getStatistikyRocni` and `student/getStatistikySuma` both 500 flat with a valid ST ticket.
